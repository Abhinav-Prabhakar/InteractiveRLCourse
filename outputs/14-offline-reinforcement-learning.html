Offline Reinforcement
Learning

Learn a policy from a fixed log of experience — with no environment to query and no second chance at the states you never visited.

01The offline setting

Offline RL — also called batch RL — hands you a fixed dataset and forbids all further interaction. The data was produced by some behavior policy $\mu$, usually unknown and usually mediocre.

$$\mathcal{D}=\big\{(s_i,a_i,r_i,s'_i)\big\}\sim\mu,\qquad \max_{\pi}\;J(\pi)=\mathbb{E}_{\pi}\!\Big[\textstyle\sum_{t}\gamma^{t}r_t\Big] \quad\text{using only }\mathcal{D}.$$

The dataset is a sample from the state distribution that $\mu$ induces — not the one $\pi$ will induce. That single mismatch is the whole chapter.

Why it matters. Logged hospital treatments, driving fleets, and recommendation feeds are all offline. The environment is not available; the counterfactual action is never observed. You get one distribution of experience and must not leave it carelessly.

02The distribution shift problem

Every value-based method improves the policy by pushing probability toward actions with high value. Offline, that push can walk straight out of the data.

$$\pi(a\mid s)>0\quad\text{where}\quad\mu(a\mid s)\approx 0.$$

Nothing in $\mathcal{D}$ constrains $Q(s,a)$ there. A function approximator will still report some value, and the $\arg\max$ will still select it. The defect is not noise — it is an unconstrained extrapolation, and bootstrapping feeds it back into every predecessor.

Give a fit too little flexibility and it cannot bend where the data does; give it too much and it bends everywhere the data does not. Either way its maximum can leave the region the data covers. Drag the slider and watch where $\hat a$ lands.

The support is the contract. Inside $\mathrm{supp}(\mu)$ the data pins $Q$ down; outside it, $Q$ is whatever your model happens to say.

03Where the blind max fails

The offline DQN objective (Chapter 10) is unchanged from the online one — only the expectation moves onto $\mathcal{D}$:

$$\mathcal{L}_{\mathrm{DQN}}(\theta)=\mathbb{E}_{(s,a,r,s')\sim\mathcal{D}}\Big[\big(r+\gamma\max_{a'}Q_\theta(s',a')-Q_\theta(s,a)\big)^2\Big].$$

The $\max_{a'}$ queries $Q_\theta$ at every action, including the ones $\mathcal{D}$ never contains. Write the fit error between the empirical backup operator $\hat{\mathcal{T}}$ and the true one $\mathcal{T}$ and it splits cleanly:

$$\hat Q-Q^*=\underbrace{\big(\mathcal{T}\hat Q-\mathcal{T}Q^*\big)}_{\le\,\gamma\|\hat Q-Q^*\|_\infty}+\underbrace{\big(\hat{\mathcal{T}}\hat Q-\mathcal{T}\hat Q\big)}_{\textbf{extrapolation error}}.$$

The first term is a $\gamma$-contraction and the data repairs it. The second is the extrapolation error identified by BCQ: the gap between the operator you fit — a regression on $\mathcal{D}$ — and the operator you wish you fit. Where the data is thin it is unbounded.

The first term is bounded; the second is not. That second term is exactly where the distribution shift is spent.

The max off-support is the enemy. Restrict the $\arg\max$ to actions $\mu$ actually takes and the error vanishes — at the cost of never improving past $\mu$. Every method below buys back some improvement for some conservatism.

04Conservative Q-learning

CQL keeps the whole action set but prices it. It adds a penalty that pushes $Q$ down everywhere except on the actions the data supports:

$$\mathcal{L}_{\mathrm{CQL}}(\theta)=\tfrac12\,\mathbb{E}_{\mathcal{D}}\big[(Q_\theta-\mathcal{B}^\pi Q_\theta)^2\big] +\alpha\,\mathbb{E}_{s\sim\mathcal{D}}\Big[\underbrace{\log\!\sum_{a}e^{Q_\theta(s,a)}}_{\text{push every action down}}-\underbrace{\mathbb{E}_{a\sim\mu}[Q_\theta(s,a)]}_{\text{hold data actions up}}\Big].$$

The $\log\sum_a e^{Q}$ is a soft maximum, so lowering it lowers the high end of $Q$; the second term holds $Q$ up only on actions $\mu$ chose. The net pressure lands on unseen actions.

Tabularly the effect has a closed form — every unsupported action drops by exactly $\alpha$:

$$\hat Q_{\mathrm{CQL}}(s,a)=\hat Q(s,a)-\alpha\,\mathbf 1\!\big[a\notin\mathcal{D}(s)\big].$$

Read the penalty back as an adversary: it finds the action with the largest $Q$ and drags it down until the data's own actions are competitive.

Conservatism is a repaired $\max$. CQL still maximizes, but over pessimistic values, so the winning action is the best one it can defend from data. Too little $\alpha$ and the phantom survives; too much and you refuse to improve at all.

06Implicit Q-learning: never ask the out-of-distribution question

IQL takes a different road. The problem was the $\max$; IQL removes it. Instead of bootstrapping from the largest next-action value, it learns a state value $V$ by expectile regression over the actions the data contains:

$$\mathcal{L}_V(\psi)=\mathbb{E}_{\mathcal{D}}\Big[L_\tau^{\mathrm{exp}}\big(Q_\theta(s,a)-V_\psi(s)\big)\Big],\qquad L_\tau^{\mathrm{exp}}(u)=\big|\tau-\mathbf 1[u<0]\big|\,u^{2}.$$

For $\tau\in(0,1)$ this is a soft maximum: $\tau\to1$ behaves like the max, $\tau=0.5$ like the mean, and every $\tau$ in between leans toward the upper tail without ever querying an action outside the batch. The value head then regresses onto the data's rewards:

$$\mathcal{L}_Q(\theta)=\mathbb{E}_{(s,a,r,s')\sim\mathcal{D}}\Big[\big(r+\gamma V_\psi(s')-Q_\theta(s,a)\big)^2\Big].$$

No term in either loss samples an action from $\pi$. The policy is extracted afterwards — an advantage-weighted behavioral clone, $\pi(a\mid s)\propto\mu(a\mid s)\exp\!\big(\beta(Q_\theta-V_\psi)\big)$ — which is why IQL is conservative-by-construction rather than penalized.

Why this is the cleanest idea in offline RL. The $\arg\max$ is where the extrapolation error entered; drop it and the question simply never arises. You give up the ability to actively prefer unseen actions, which is precisely the ability that was unsafe.

07The rest of the family

CQL and IQL are two entry points into one idea — do not trust $Q$ where $\mu$ did not go. The remaining methods implement the same discipline differently.

Restrict the action set

BCQ trains a generative model $\hat\mu(a\mid s)$ and perturbs only actions near the data manifold, then maximizes over that restricted set — the max can no longer leave $\mathrm{supp}(\mu)$.

Regularize the actor toward the data

TD3+BC appends a plain behavioral-cloning term to the deterministic actor:

$$\pi=\arg\max_\pi\;\mathbb{E}_{s\sim\mathcal{D}}\Big[\lambda\,Q(s,\pi(s))-\big(\pi(s)-a\big)^2\Big],\quad \lambda=\frac{\alpha}{\frac1N\sum_s|Q(s,\pi(s))|}.$$

AWAC reweights the actor update by $\exp\!\big(A(s,a)/\lambda\big)$, so the policy moves toward actions the data says are good and ignores the rest.

Say the word “model”

Model-based offline RL (MOPO, MOReL) fits a dynamics model on $\mathcal{D}$ and marks regions of low data density as high-uncertainty; the planner is penalized by that uncertainty, so it never rolls out into the unknown. It is CQL’s pessimism, applied to imagination.

Skip the value function entirely

The Decision Transformer models the whole trajectory with a sequence model conditioned on a target return. It never bootstraps and never computes a $\max$ — so it cannot extrapolate a value at all, only replay the patterns in the log at the quality you request.

Evaluation is the quiet problem

You cannot run $\pi$ to score it. The offline tools are importance sampling and fitted Q-evaluation (FQE — learn $Q^\pi$ on $\mathcal{D}$ and average). Both inherit the same support assumption; an over-optimistic value function scores a policy well and lies.

08Summary

Offline RL is one failure mode with one fix:

$$\text{extrapolation error}\;\Longrightarrow\;\text{don't trust }Q\text{ off }\mathrm{supp}(\mu).$$
  • The dataset is one sample from $\mu$’s state distribution; $\pi$ will induce another.
  • The blind $\max_{a'}Q$ queries actions the data never covered, and bootstrapping amplifies the answer.
  • The error separates into a contracting on-support part and an unbounded extrapolation part.
  • CQL penalizes off-support actions by $\alpha$; IQL removes the out-of-distribution question by never asking it.
  • Every other method — BCQ, AWAC, TD3+BC, model-based, Decision Transformer — is the same pessimism wearing a different mask.
  • Raise behavior coverage and the problem softens; you rarely get to choose the behavior policy.
