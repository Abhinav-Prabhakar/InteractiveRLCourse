Hierarchical
Reinforcement Learning

Flat RL relearns every step of a long journey. Give the agent temporally extended actions and it learns the journey's stages once, then recombines them.

01Why horizons break flat RL

Every tabular method so far propagates information exactly one primitive step per backup. When a reward finally arrives, a single Bellman sweep nudges it one state closer to the start.

$$V(s)\leftarrow\max_a\Big[R^a_s+\gamma\sum_{s'}P^a_{ss'}\,V(s')\Big]\qquad\text{— one step of lookahead}$$

A goal $n$ primitive steps away therefore needs about $n$ sweeps before its value reaches the start, and the signal arrives attenuated by $\gamma^{\,n}$. Worse, the agent relearns the same sub-skill at every position: walking to the door from one room differs only cosmetically from walking to it from another.

Long horizons — not large state spaces — are what make this hard. The number of backups scales with the length of the solution, and the value signal decays as $\gamma^{\,n}$. Learning at what timescale to act is the escape: an action that spans many steps moves value many steps at once.

02The options framework

An option is a temporally extended action: a little policy that runs for several steps and then stops. Formally it is a triple $\omega=(I_\omega,\pi_\omega,\beta_\omega)$.

$$\omega=(I_\omega,\ \pi_\omega,\ \beta_\omega),\qquad I_\omega\subseteq\mathcal{S},\qquad \pi_\omega(a\mid s),\qquad \beta_\omega:\mathcal{S}\to[0,1].$$

$I_\omega$ is the initiation set — the states where the option may start. $\pi_\omega$ is the intra-option policy it follows while active. $\beta_\omega(s)=0$ while the option should keep running and rises as it should terminate. A primitive action is the degenerate option with $I_\omega=\mathcal{S}$, a point-mass policy, and $\beta_\omega\equiv 1$. A policy over options $\pi_\Omega(o\mid s)$ therefore chooses only among macros, not among steps.

Option values

Run option $o$ from $s$ and let $\tau$ be the (random) number of primitive steps until it terminates. The option-value function sums the rewards earned along the way, then bootstraps from wherever the option left the agent:

$$Q_\Omega(s,o)=\mathbb{E}\!\left[\sum_{j=0}^{\tau-1}\gamma^{\,j}R_{t+j+1}+\gamma^{\,\tau}V_\Omega(S_{t+\tau})\ \middle|\ S_t=s,\ o_t=o\right],\qquad V_\Omega(s)=\sum_o\pi_\Omega(o\mid s)\,Q_\Omega(s,o).$$

Optimizing over the high-level and the intra-option policies jointly gives the option Bellman equation:

$$Q_*(s,o)=\mathbb{E}\!\left[r_1+\gamma r_2+\cdots+\gamma^{\,\tau-1}r_\tau+\gamma^{\,\tau}\max_{o'}Q_*(s_{t+\tau},o')\ \middle|\ s_t=s,\ o_t=o\right].$$

Read that last line back: the flat backup's single-step lookahead is replaced by a $\tau$-step lookahead whose bootstrap is discounted by $\gamma^{\tau}$. The exponent $\tau$ is the whole story. One backup now carries value across an entire option instead of a single move.

03Composing options in a two-room world

A $9\times5$ grid split by a wall into two rooms, joined only by a locked door. A key sits in the left room, the goal in the right. An agent that walks step by step must first find the key, then the door, then the goal — and the flat backup pays for all three journeys one move at a time.

Assume three low-level options are already learned: go-to-key, go-to-door (which crosses into the right room once the key is held), and go-to-goal. Each carries its own shortest-path intra-option policy. The high-level agent then faces a tiny decision problem: in what order to call them?

The high-level problem is small on purpose. With skills in hand, the agent chooses among three options instead of four moves at every cell, so each backup advances the value by $\tau$ steps. That is precisely where the sample-efficiency gap in the chart comes from — not from better exploration, but from coarser credit assignment.

04The option-critic architecture

So far the options were given. The option-critic learns them: the intra-option policies $\pi_{\theta_\pi}$ and the termination functions $\beta_{\theta_\beta}$ are parameterized and differentiated alongside the policy over options. The signal that shapes termination is the advantage of continuing, $A_\Omega(s,o)=Q_\Omega(s,o)-V_\Omega(s)$.

$$\frac{\partial\mathcal{L}}{\partial\theta_\beta}=-\mathbb{E}\!\left[\gamma^{\,\tau}A_\Omega(s_{t+\tau},o)\,\nabla_{\theta_\beta}\beta_{\theta_\beta}(s_{t+\tau})\right]\;+\;\text{(terms for terminations inside the option)}.$$

The leading term is the load-bearing one: it raises termination probability exactly where continuing the current option has negative advantage, so a losing option is cut short and the agent re-plans. The intra-option policy is trained by the usual policy gradient, with the advantage of the option it belongs to:

$$\frac{\partial\mathcal{L}}{\partial\theta_\pi}=\mathbb{E}\!\left[\sum_t \gamma^{\,t}\,\nabla_{\theta_\pi}\log\pi_{\theta_\pi}(a_t\mid s_t)\,A_\Omega(s_t,o_t)\right].$$

Termination acts like a learned, state-dependent boundary of the option. Two limits make its role concrete: force $\beta\equiv 1$ and every option collapses to a primitive action; force $\beta\equiv 0$ and the agent commits to one option forever. Useful hierarchies live in between.

Termination is the dial between flat and abstract. Both objectives above are ordinary policy gradients — the only new ingredient is $\gamma^{\,\tau}$, the discount that travels with the option and makes each update aware of how long the option actually lasted.

05Feudal RL and goal-conditioned hierarchies

Feudal RL splits the agent in two. A manager sets a goal $g$ — a state to reach, in a low-dimensional space — and a worker is a goal-conditioned policy $\pi_W(a\mid s,g)$ that acts to achieve it. The manager never chooses primitive actions; it chooses subgoals, and is rewarded when the worker makes progress toward them.

$$g\sim\pi_M(g\mid s),\qquad a\sim\pi_W(a\mid s,g),\qquad V(s,g)=\mathbb{E}\!\left[\sum_{k=0}^{\infty}\gamma^{\,k}R_{t+k+1}\ \middle|\ S_t=s,\ g\right].$$

The worker's value $V(s,g)$ is exactly an option-value function whose option is "reach $g$". Because goals are just an extra input, one worker network can cover a whole family of subgoals — a universal value function approximately factorizes as $Q(s,a,g)\approx\phi(s,a)^{\top}\psi(g)$, sharing structure across every goal.

This is the same idea as options with the alarm clock moved inside the policy. Where options terminate on a learned $\beta_\omega$, a goal-conditioned worker terminates when $g$ is reached. Both replace a long primitive sequence with a single decision, and both are how a hierarchy composes an open-ended repertoire of skills.

Cheat sheet

$$\begin{aligned} \omega &= (I_\omega,\ \pi_\omega,\ \beta_\omega),\qquad \pi_\Omega(o\mid s) \\[2pt] Q_\Omega(s,o) &= \mathbb{E}\!\left[\textstyle\sum_{j=0}^{\tau-1}\gamma^{\,j}R_{t+j+1}+\gamma^{\,\tau}V_\Omega(S_{t+\tau})\right],\qquad V_\Omega(s)=\sum_o\pi_\Omega(o\mid s)Q_\Omega(s,o) \\[2pt] Q_*(s,o) &= \mathbb{E}\!\left[r_1+\gamma r_2+\cdots+\gamma^{\,\tau-1}r_\tau+\gamma^{\,\tau}\max_{o'}Q_*(s_{t+\tau},o')\right] \\[2pt] \frac{\partial\mathcal{L}}{\partial\theta_\beta} &= -\mathbb{E}\!\left[\gamma^{\,\tau}A_\Omega(s_{t+\tau},o)\,\nabla_{\theta_\beta}\beta_{\theta_\beta}(s_{t+\tau})\right] \\[2pt] V(s,g) &= \mathbb{E}\!\left[\textstyle\sum_{k=0}^{\infty}\gamma^{\,k}R_{t+k+1}\ \middle|\ S_t=s,\ g\right],\qquad a\sim\pi_W(a\mid s,g) \end{aligned}$$

Everything downstream — multi-agent games, meta-learning over task families, and the goal-conditioned policies that drive language-model agents — is a choice about which timescale a single Bellman backup should span.
