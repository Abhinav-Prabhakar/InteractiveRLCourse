Offline RL
Benchmark

One frozen log, four learners, and a leaderboard — train naive TD, CQL, IQL and BCQ on the same gridworld data, then interrogate what each believes about actions the log never took.

01The bench

Offline reinforcement learning is easiest to measure when nothing is allowed to hide. The environment is a $4\times4$ gridworld with four deterministic moves; the goal pays $+1$, a pit pays $-1$, every other step costs $0.3$, and discounting is $\gamma=0.9$. With those numbers the optimal value of every cell can be written down exactly, so a learner's estimate can be compared against the truth at every step — no evaluation rollouts, no confidence intervals, no excuses.

The catch is the data. A fixed behaviour policy walks the grid and writes down what it did. Some state–action pairs are visited constantly; others are never tried. The learner only ever sees the second-hand log. Everything below is the same log, the same reward scale, and the same eight hundred gradient steps; the only thing that changes is what each method does when the log has nothing to say about an action.

States are numbered row-major from $0$ to $15$. Terminal cells are the goal ($3$) and the pit ($9$); the start is $13$. The behaviour policy is $\varepsilon$-greedy toward the goal, so the log is dominated by the corridor up the right edge — the cells a shortest path actually visits.

Why a tabular bench? Because the failure mode of offline RL is not approximation error — it is asking a function to be confident about an action it has never seen. A $16$-state problem isolates exactly that, and lets the leaderboard be honest about which method was actually conservative versus merely lucky.

02The fixed log

Collected data is the whole experiment. Write a behaviour policy, roll it out, and keep the transitions. The policy below moves toward the goal most of the time and otherwise picks uniformly; the dataset is a uniform sample of non-terminal states, which is what makes the coverage map interesting — some cells are sampled but their outgoing actions are not.

Coverage is not the same as visitation. A state can appear hundreds of times in the log while only one of its four actions ever appears, and an offline learner that maximises over all four will happily assign a large value to the three it never saw. The heatmap counts actions seen per state, not states seen, because that is the quantity the learners actually depend on.

Collecting and logging the data

The collection script is deliberately boring. One pass produces a list of transitions, each of which is a state, an action, a reward, and a next state. There are no rewards for exploration and no resets inside an episode: when the agent reaches the goal or the pit the episode ends and a fresh one starts at $12$.

log_dataset.pyPython
import numpy as np

GOAL, PIT, START = 3, 9, 13
STEP_COST, GAMMA = 0.3, 0.9
MOVES = [(-1, 0), (0, 1), (1, 0), (0, -1)]  # up, right, down, left

def step(s, a):
    r, c = divmod(s, 4)
    dr, dc = MOVES[a]
    nr, nc = r + dr, c + dc
    if not (0 <= nr < 4 and 0 <= nc < 4):
        return s, -STEP_COST, False
    ns = nr * 4 + nc
    if ns == GOAL:
        return ns, 1.0, True
    if ns == PIT:
        return ns, -1.0, True
    return ns, -STEP_COST, False

def dist(s):
    r, c = divmod(s, 4)
    return r + (3 - c)          # rows and columns to the goal cell 3 (top-right)

def behavior(s, eps, rng):
    if rng.random() < eps:
        return int(rng.integers(4))
    prog = []
    for a in range(4):
        ns, _, _ = step(s, a)
        prog.append((dist(s) - dist(ns), -6.0 if ns == PIT else 0.0))
    best = max(p[0] for p in prog)
    cand = [a for a, p in enumerate(prog) if p[0] == best and p[1] == 0.0]
    return int(rng.choice(cand))

def collect(n_pairs=500, eps=0.05, seed=4242):
    rng = np.random.default_rng(seed)
    non_terminal = [s for s in range(16) if s not in (GOAL, PIT)]
    log = []
    while len(log) < n_pairs:
        s = int(rng.choice(non_terminal))       # uniform over non-terminal states
        a = behavior(s, eps, rng)
        ns, r, done = step(s, a)
        log.append((s, a, r, ns, done))
    return log
The trap is in the sampler. Every state is drawn, but the log stores only the single action the behaviour policy took there. The shortest-path action appears thousands of times; the other three are missing entirely unless $\varepsilon$ scatters a few in. That is realistic — logs are collected by policies with an agenda — and it is precisely the asymmetry that separates the four learners.

03Four ways to stay in the data

All four learners share the same skeleton: a table of action-values $Q(s,a)$, one Bellman target per transition, and mean-squared error. They differ in a single line — how the target is computed from the next state. That line is where an offline algorithm lives or dies.

Naive TD uses the maximum over all four actions, exactly as in online Q-learning. It has no idea which actions are in the log, so its targets chase values it cannot possibly have earned. CQL keeps the same regression but clamps every action's value from below by the smallest value it has support for, minus a margin $\alpha$; unsupported actions are pushed down while supported ones are left alone. IQL never evaluates the policy's actions at all: it fits $V(s)$ as an expectile of $Q$ over the actions present in the data, then regresses $Q$ toward the reward plus discounted $V$. BCQ is the blunt instrument — it simply refuses to consider actions that were never logged, taking a maximum only over the support.

The learner, in one file

Every shared piece of machinery — Bellman targets, the replay loop, and the three conservative variants — fits in about sixty lines. The support mask is the only bookkeeping the offline setting adds.

offline_learners.pyPython
import numpy as np

def bellman_targets(log, Q, gamma, V=None):
    S  = np.array([t[0] for t in log])
    A  = np.array([t[1] for t in log])
    R  = np.array([t[2] for t in log])
    NS = np.array([t[3] for t in log])
    D  = np.array([t[4] for t in log], dtype=float)
    nxt = Q[NS].max(axis=1) if V is None else V[NS]
    y = R + gamma * (1.0 - D) * nxt
    return S, A, y

def batch_update(Q, S, A, y, lr):
    """Mean TD error per (s, a) pair, so rare pairs learn as fast as common ones."""
    flat = S * Q.shape[1] + A
    err = Q[S, A] - y
    g = np.bincount(flat, weights=err, minlength=Q.size)
    c = np.bincount(flat, minlength=Q.size).astype(float)
    seen = c > 0
    Q.reshape(-1)[seen] -= lr * g[seen] / c[seen]

def train_naive(log, n_act, n_st, steps=1500, lr=0.5, seed=0):
    Q = np.zeros((n_st, n_act))
    for _ in range(steps):
        S, A, y = bellman_targets(log, Q, 0.9)
        batch_update(Q, S, A, y, lr)
    return Q

def support_mask(log, n_act, n_st):
    m = np.zeros((n_st, n_act), dtype=bool)
    for s, a, *_ in log:
        m[s, a] = True
    return m

def train_cql(log, n_act, n_st, alpha=0.4, steps=1500, lr=0.5):
    sup = support_mask(log, n_act, n_st)
    Q = np.zeros((n_st, n_act))
    for _ in range(steps):
        S, A, y = bellman_targets(log, Q, 0.9)
        batch_update(Q, S, A, y, lr)
        mins = np.where(sup, Q, np.inf).min(axis=1, keepdims=True)   # min over support
        floor = np.where(sup, Q, mins - alpha)                       # clamp the rest below
        Q = np.minimum(Q, floor)
    return Q

def train_iql(log, n_act, n_st, tau=0.9, steps=1500, lr=0.5):
    sup = support_mask(log, n_act, n_st)
    Q, V = np.zeros((n_st, n_act)), np.zeros(n_st)
    for _ in range(steps):
        for _ in range(3):                                            # expectile step
            w = np.where(np.where(sup, Q - V[:, None], -1.0) > 0, tau, 1.0 - tau)
            w = np.where(sup, w, 0.0)
            Vs = (w * Q).sum(1) / np.maximum(w.sum(1), 1e-9)
            V = V + lr * (Vs - V)
        S, A, y = bellman_targets(log, Q, 0.9, V=V)
        batch_update(Q, S, A, y, lr)
    return Q

def train_bcq(log, n_act, n_st, steps=1500, lr=0.5):
    sup = support_mask(log, n_act, n_st)
    Q = np.zeros((n_st, n_act))
    for _ in range(steps):
        masked = np.where(sup, Q, -1e9)
        S, A, y = bellman_targets(log, masked, 0.9)
        batch_update(Q, S, A, y, lr)
    return Q
Full-batch vs. sampled. The in-page trainer loops over the whole log each step for determinism and speed at this scale; real implementations sample minibatches. The sign of every result here is identical under minibatching, which is exactly why this bench is useful.

04What a method believes off-support

Training curves mostly agree, so the interesting question is what happens to a single action value the log never touched. Pick a state and slide across a continuous action coordinate: $0$ is up, $1$ is right, $2$ is down, $3$ is left. Inside the data support the four learners interpolate between the values they actually fitted. Outside it, each method's rule takes over — and the rules disagree loudly.

Naive TD has no rule at all, so an unsupported action keeps the value it was initialised with and the curve jumps upward the moment it leaves the data. CQL pushes unsupported values down toward the smallest supported value minus $\alpha$, so the curve flattens below the data. IQL has no per-action off-support behaviour — it reports the state value $V(s)$ and stays there. BCQ does the honest thing and refuses to draw anything outside the support: the action simply has no value under that policy.

The shaded band marks the support hull $[\min a_i,\ \max a_i]$ over actions present in the log for this state. Everything outside it is where the methods stop describing data and start describing themselves.

This is the heart of the offline problem, and it is not a tabular curiosity. In a continuous-action setting the max over a learned critic is an optimisation problem, and an over-estimated critic makes the argmax run away from the data. CQL's penalty and BCQ's support constraint are two different answers to the same question: how do you stop a maximum from becoming a search for fiction? IQL sidesteps the question by not taking a maximum over actions at inference time until it has to.

05Fine-tuning, or why the head start matters

Offline pre-training is usually a warm start, not a destination. The question is whether a conservative learner gives online fine-tuning a better beginning than starting from zero — and whether its pessimism becomes a handicap once real interaction is allowed.

Each frozen learner is used as the initialisation for the same online $\varepsilon$-greedy Q-learning agent. The plot tracks the true value of the current $\varepsilon$-greedy policy at checkpoints, not the TD error, so it is a step ahead of the learned table and stays smooth. A good offline initialisation hands the online agent a policy that is already on the plateau near $V^\star$; a bad one starts near $-1.1$ and has to climb.

Three things are worth checking. First, whether the conservative methods hand over a policy that is already on the plateau — CQL, IQL and BCQ start at the top of the plot and barely move. Second, whether naive TD's head start survives contact with real rewards: it does not, because the first online updates puncture values the log never supported, and its curve climbs from the bottom together with the from-scratch baseline. Third, whether a very conservative method is slow to recover: raise $\varepsilon$ and watch whether the conservative curves ever leave the plateau as the online agent explores.

The fine-tuning loop

Online updates are ordinary Q-learning on the same grid; the only offline-specific code is the initialisation. Actions a method refused to value start at the smallest supported value minus one — the same pessimism the learner already expressed — while CQL arrives already clamped and naive TD keeps its optimistic zeros. The curve evaluates the $\varepsilon$-greedy policy exactly by policy evaluation, so it reflects behaviour, not just the table.

finetune.pyPython
import numpy as np

def soft_policy_value(Q, eps):
    """Exact value of the eps-greedy policy induced by Q (policy evaluation)."""
    V = np.zeros(Q.shape[0])
    for _ in range(500):
        delta = 0.0
        for s in range(Q.shape[0]):
            if s in (3, 9):
                continue
            pi = np.full(4, eps / 4)
            pi[int(np.argmax(Q[s]))] += 1.0 - eps
            v = 0.0
            for a in range(4):
                ns, r, done = step(s, a)
                v += pi[a] * (r + (0.0 if done else 0.9 * V[ns]))
            delta = max(delta, abs(v - V[s]))
            V[s] = v
        if delta < 1e-12:
            break
    return V

def prepare(Q0, support, eps=1.0):
    """Unsupported actions start one point below the smallest supported value."""
    Q = Q0.copy()
    for s in range(Q.shape[0]):
        known = support[s]
        if known.any():
            Q[s, ~known] = Q[s, known].min() - eps
    return Q

def finetune(Q0, steps=1500, lr=0.15, eps=0.12, seed=7):
    rng = np.random.default_rng(seed)
    Q, s = Q0.copy(), 13
    curve = [(0, soft_policy_value(Q0, eps)[13])]
    for t in range(1, steps + 1):
        a = int(rng.integers(4)) if rng.random() < eps else int(np.argmax(Q[s]))
        ns, r, done = step(s, a)
        target = r + (0.0 if done else 0.9 * Q[ns].max())
        Q[s, a] += lr * (target - Q[s, a])
        s = 13 if done else ns
        if t % 100 == 0:
            curve.append((t, soft_policy_value(Q, eps)[13]))
    return Q, curve
Read the starting point, not just the endpoint. Any online agent converges eventually on a problem this small. The offline question is how much interaction the warm start saves — and whether a pessimistic initialisation ever recovers the value it suppressed.

06The leaderboard

Two numbers decide the table. The first is the value each learner claims for the start state, $\hat V(13)$ — what the agent thinks it will get. The second is what it actually gets when you follow its greedy policy to the end, $\mathbb{E}[G]$ — what the policy is worth on the real grid. The gap between them is the overestimation the offline setting is famous for, and only the conservative methods keep it small.

The point of the whole exercise: offline RL is not about learning faster, it is about learning without permission to explore. Every algorithm here is a different answer to the same question — what should a value be when there is no data to justify it?
