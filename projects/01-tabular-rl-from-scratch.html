01Build the MDP

Everything below runs on one gridworld you define here. Paint walls, drop terminals with rewards, set the per-step cost and the slip probability. The page rebuilds the Markov decision process and re-solves it on every edit.

The world is the usual tuple $(\mathcal{S},\mathcal{A},P,R,\gamma)$. There are four actions — up, right, down, left — and with probability $\text{slip}$ the move is diverted to a neighbouring action:

$$P(s'\mid s,a)=\sum_{b}\pi_{\text{slip}}(b\mid a)\,\mathbf{1}\{\text{move}(s,b)=s'\},\qquad R(s,s')=\text{step}+r(s')$$

The reward is paid on entry, so a terminal pays once, and a move into a wall keeps you in place and pays only the step cost. A policy is an action per live cell; the optimal one is what every algorithm on this page is hunting.

Deliverable: convergence plots for every solver on your grid, a steps-and-episodes-to-converge table, and an interactive trace viewer that replays the learned policy with traces and Dyna toggled.

Build order

  1. Environment. Store rew, term, wall per cell and the transition rule. This is the only ground truth; the model never moves.
  2. Exact solvers. Value iteration and policy iteration read $P$ and $R$ directly and produce $V_*,Q_*,\pi_*$.
  3. Sample-based control. Monte Carlo, Sarsa and Q-learning see only trajectories. Compare their sample efficiency against the exact curve.
  4. Traces and planning. Add Sarsa($\lambda$) and Dyna-Q, then replay the trajectory and watch credit spread backward.

Bellman optimality check

The environment is the whole substrate. Write it once, exactly, and every solver afterwards is a few lines.

env.pypython
import numpy as np

class GridWorld:
    """A small tabular MDP: walls, terminal cells, a per-step cost, and slip."""
    def __init__(self, rows, cols, start, rew, term, wall,
                 step=-0.04, gamma=0.95, slip=0.1):
        self.R, self.C = rows, cols
        self.start = np.ravel_multi_index(start, (rows, cols))
        self.rew  = np.asarray(rew,  dtype=float).ravel()
        self.term = np.asarray(term, dtype=bool).ravel()
        self.wall = np.asarray(wall, dtype=bool).ravel()
        self.step, self.gamma, self.slip = step, gamma, slip
        self.n, self.A = rows * cols, 4                # up, right, down, left
        self.dirs = [(-1, 0), (0, 1), (1, 0), (0, -1)]

    def move(self, s, a):
        r, c = divmod(s, self.C)
        dr, dc = self.dirs[a]
        r2, c2 = r + dr, c + dc
        if not (0 <= r2 < self.R and 0 <= c2 < self.C):
            return s                                   # bounce off the border
        s2 = r2 * self.C + c2
        return s if self.wall[s2] else s2

    def transitions(self, s, a):
        """P(. | s, a): intended move, plus two slips at half weight each."""
        out = {}
        for b, p in ((a, 1 - self.slip),
                     ((a + 1) % 4, self.slip / 2),
                     ((a + 3) % 4, self.slip / 2)):
            if p > 0:
                s2 = self.move(s, b)
                out[s2] = out.get(s2, 0.0) + p
        return out

    def reward(self, s, s2):
        return self.step + (self.rew[s2] if s2 != s else 0.0)

    def sample(self, s, a, rng):
        u, acc = rng.random(), 0.0
        for s2, p in self.transitions(s, a).items():
            acc += p
            if u <= acc + 1e-12:
                return s2, self.reward(s, s2)
        return s, self.reward(s, s)

02Exact solution from the model

With $P$ and $R$ in hand you can skip sampling entirely. Policy evaluation repeatedly applies the Bellman expectation backup until the value function stops moving; policy improvement then acts greedily on it. Alternating the two is policy iteration.

$$v_{k+1}(s)=\sum_a \pi(a\mid s)\sum_{s'}p(s'\mid s,a)\big[r+\gamma v_k(s')\big],\qquad \pi'(s)=\arg\max_a q_\pi(s,a)$$

Value iteration folds the two into one sweep of the optimality operator — evaluate and improve in the same pass. It converges because that operator is a $\gamma$-contraction in the sup norm: the residual $\lVert v_{k+1}-v_k\rVert_\infty$ shrinks by at least a factor $\gamma$ every sweep.

$$v_{k+1}(s)=\max_a\sum_{s'}p(s'\mid s,a)\big[r+\gamma v_k(s')\big]$$

The residual is not only a stopping rule. It is the quantity this project plots and compares.

value_iteration.pypython
def value_iteration(env, tol=1e-3):
    """Bellman optimality backups until the sup-norm residual stops changing."""
    V = np.zeros(env.n)
    deltas, sweeps = [], 0
    while True:
        V_old = V.copy()
        for s in range(env.n):
            if env.term[s] or env.wall[s]:
                continue
            V[s] = max(
                sum(p * (env.reward(s, s2) + env.gamma * V_old[s2])
                    for s2, p in env.transitions(s, a).items())
                for a in range(env.A))
        delta = np.max(np.abs(V - V_old))              # ||v_{k+1} - v_k||_inf
        deltas.append(delta)
        sweeps += 1
        if delta < tol:
            break
    Q = [[sum(p * (env.reward(s, s2) + env.gamma * V[s2])
              for s2, p in env.transitions(s, a).items())
          for a in range(env.A)] for s in range(env.n)]
    return V, np.array(Q), deltas, sweeps
policy_iteration.pypython
def policy_evaluation(env, pi, tol=1e-3):
    V = np.zeros(env.n)
    while True:
        V_old = V.copy()
        for s in range(env.n):
            if env.term[s] or env.wall[s]:
                continue
            V[s] = sum(p * (env.reward(s, s2) + env.gamma * V_old[s2])
                       for s2, p in env.transitions(s, pi[s]).items())
        if np.max(np.abs(V - V_old)) < tol:
            return V

def policy_iteration(env, tol=1e-3):
    """Evaluate the current policy, then act greedily; stop when it is stable."""
    pi = np.zeros(env.n, dtype=int)
    V_prev, dv, iters = np.zeros(env.n), [], 0
    while True:
        V = policy_evaluation(env, pi, tol)
        dv.append(np.max(np.abs(V - V_prev)))       # movement between policies
        V_prev = V
        stable = True
        for s in range(env.n):
            if env.term[s] or env.wall[s]:
                continue
            q = [sum(p * (env.reward(s, s2) + env.gamma * V[s2])
                     for s2, p in env.transitions(s, a).items())
                 for a in range(env.A)]
            best = int(np.argmax(q))
            if q[best] > q[pi[s]] + 1e-12:
                pi[s] = best
                stable = False
        iters += 1
        if stable:
            break
    return pi, V, dv, iters

Both solvers sweep the same tables and cost roughly $O(|\mathcal{S}|^2|\mathcal{A}|)$ per pass with a dense model. On a grid that is nothing; the race below is decided by the number of passes, not the cost of one.

03Control from samples

Now take the model away. The agent sees one transition at a time and must estimate action values from returns. Monte Carlo control waits for the episode to end, computes the return of every visited pair, and averages. Sarsa and Q-learning replace the whole return with a one-step bootstrap.

$$Q(S_t,A_t)\leftarrow Q(S_t,A_t)+\alpha\big[R_{t+1}+\gamma\,\square-Q(S_t,A_t)\big]$$

The blank is the entire difference between the two TD methods: Sarsa fills in $Q(S_{t+1},A_{t+1})$ for the action the behaviour policy actually takes, so it evaluates the $\varepsilon$-greedy policy it runs. Q-learning fills in $\max_a Q(S_{t+1},a)$, so it evaluates the greedy policy no matter how the data was generated.

Monte Carlo has no blank. Its target is the sampled return $G_t$, which is unbiased but high variance and unavailable until the episode ends:

$$Q(S_t,A_t)\leftarrow Q(S_t,A_t)+\alpha\big[G_t-Q(S_t,A_t)\big]$$
Every one of these is the same running-average update. Change the target and you change the estimator; change the behaviour policy and you change what data the estimator sees. That is the whole family.
mc_control.pypython
def eps_greedy(q, eps, rng):
    if rng.random() < eps:
        return int(rng.integers(len(q)))
    return int(np.argmax(q))

def mc_control(env, episodes=2000, eps=0.1, gamma=0.95, rng=None):
    """First-visit Monte Carlo control with an epsilon-greedy policy."""
    Q = np.zeros((env.n, env.A))
    N = np.zeros((env.n, env.A))
    for _ in range(episodes):
        traj, s = [], env.start
        for _ in range(200):
            a = eps_greedy(Q[s], eps, rng)
            s2, r = env.sample(s, a, rng)
            traj.append((s, a, r))
            s = s2
            if env.term[s]:
                break
        G, seen = 0.0, set()
        for s, a, r in reversed(traj):
            G = r + gamma * G
            if (s, a) in seen:
                continue
            seen.add((s, a))
            N[s, a] += 1
            Q[s, a] += (G - Q[s, a]) / N[s, a]       # running mean of returns
    return Q
td_control.pypython
def sarsa(env, episodes=2000, alpha=0.1, eps=0.1, rng=None):
    """On-policy TD control: the target is the action the policy really takes."""
    Q = np.zeros((env.n, env.A))
    for _ in range(episodes):
        s = env.start
        a = eps_greedy(Q[s], eps, rng)
        for _ in range(200):
            s2, r = env.sample(s, a, rng)
            if env.term[s2]:
                target = r
            else:
                a2 = eps_greedy(Q[s2], eps, rng)
                target = r + env.gamma * Q[s2, a2]
            Q[s, a] += alpha * (target - Q[s, a])
            if env.term[s2]:
                break
            s, a = s2, a2
    return Q

def q_learning(env, episodes=2000, alpha=0.1, eps=0.1, rng=None):
    """Off-policy TD control: the target is the greedy action, whatever we did."""
    Q = np.zeros((env.n, env.A))
    for _ in range(episodes):
        s = env.start
        for _ in range(200):
            a = eps_greedy(Q[s], eps, rng)
            s2, r = env.sample(s, a, rng)
            target = r + env.gamma * np.max(Q[s2])
            Q[s, a] += alpha * (target - Q[s, a])
            s = s2
            if env.term[s]:
                break
    return Q

All three share the $\varepsilon$-greedy behaviour policy, so the comparison is clean: same state space, same start, same exploration floor. Only the target differs.

04The algorithm race

Run all five on the grid you just built. The exact solvers are charged in sweeps of the Bellman operator; the sample-based learners are charged in episodes of real interaction. Both axes are logarithmic, so a straight line means geometric progress.

Each run measures its own wall-clock time. On a small grid the exact methods finish in microseconds; the learners need hundreds of episodes for the same accuracy. That gap is the price of not having a model — and the reason planning, later in this project, is worth the effort.

05Eligibility traces and Dyna

One-step TD gives credit to the pair just used. That is slow when a reward arrives many steps after the decision that earned it. An eligibility trace fixes the lag by remembering how recently each pair was visited, then spreading a single TD error backward over that memory.

$$\begin{aligned} \delta_t &= R_{t+1}+\gamma Q(S_{t+1},A_{t+1})-Q(S_t,A_t)\\[2pt] E_t(s,a) &= \gamma\lambda\,E_{t-1}(s,a)+\mathbf{1}(s=S_t,\,a=A_t)\\[2pt] Q(s,a) &\leftarrow Q(s,a)+\alpha\,\delta_t\,E_t(s,a)\quad\text{for all }(s,a) \end{aligned}$$

The trace fades by $\gamma\lambda$ every step and takes a unit bump at the pair just visited. With $\lambda=0$ the algorithm is exactly Sarsa; with $\lambda\to1$ credit reaches arbitrarily far back. One scalar error now updates every pair, weighted by eligibility.

Planning with a learned model

Dyna-Q turns the same Q-learning update into a planning step. Every real transition is stored in a sample model $\hat M$, and after each real update the agent draws $n$ stored pairs and backs them up as if they had just happened.

$$\underbrace{\text{act}}_{\text{real}}\;\longrightarrow\;\underbrace{\text{learn}}_{\text{real}}\;\longrightarrow\;\underbrace{\text{plan}\times n}_{\text{model}}$$

The update does not care where the transition came from. That is the entire trick: computation is cheap, interaction is not, so convert one into the other.

Traces and planning attack the same problem from opposite ends. Traces squeeze more learning out of one trajectory; planning squeezes more trajectories out of one transition. Both reduce the number of real steps needed to reach a good policy.
sarsa_lambda.pypython
def sarsa_lambda(env, episodes=500, alpha=0.1, lam=0.9, eps=0.1, rng=None):
    """Sarsa(lambda): one TD error is spread back over the whole trace."""
    Q = np.zeros((env.n, env.A))
    for _ in range(episodes):
        E = np.zeros((env.n, env.A))
        s = env.start
        a = eps_greedy(Q[s], eps, rng)
        for _ in range(200):
            s2, r = env.sample(s, a, rng)
            a2 = eps_greedy(Q[s2], eps, rng)
            target = r if env.term[s2] else r + env.gamma * Q[s2, a2]
            delta = target - Q[s, a]                 # the one scalar error
            E *= env.gamma * lam                     # every trace fades
            E[s, a] += 1.0                           # bump the pair just used
            Q += alpha * delta * E                   # broadcast it backward
            if env.term[s2]:
                break
            s, a = s2, a2
    return Q
dyna_q.pypython
def dyna_q(env, episodes=200, n=10, alpha=0.1, eps=0.1, rng=None):
    """Dyna-Q: every real step stores a transition, then n imagined updates."""
    Q = np.zeros((env.n, env.A))
    model = {}                                       # (s, a) -> (s', r)
    for _ in range(episodes):
        s = env.start
        for _ in range(200):
            a = eps_greedy(Q[s], eps, rng)
            s2, r = env.sample(s, a, rng)
            Q[s, a] += alpha * (r + env.gamma * np.max(Q[s2]) - Q[s, a])
            model[(s, a)] = (s2, r)                  # remember what happened
            for _ in range(n):                       # plan in the model
                (ps, pa), (ps2, pr) = rng.choice(list(model.items()))
                Q[ps, pa] += alpha * (pr + env.gamma * np.max(Q[ps2]) - Q[ps, pa])
            s = s2
            if env.term[s]:
                break
    return Q

06The trace viewer

Now watch it happen on the grid. The agent starts at S and acts $\varepsilon$-greedily on its own table. With traces off it runs Q-learning; with traces on it runs Sarsa($\lambda$) and every visited pair glows with its eligibility. The planning slider runs Dyna updates after each real step.

Step through a few episodes, then switch traces on. The glow follows the trajectory backward from the reward, and the greedy policy sharpens faster than it does without traces. Push $n$ up and the policy improves again on the same real experience — nothing about the environment changed.

07What to compare

The deliverables are plots, not opinions. On your own grid, measure four things and report them together:

QuestionWhat to plot
Exact convergence$\lVert v_{k+1}-v_k\rVert_\infty$ against sweeps for value iteration and policy iteration.
Sample efficiency$\lVert Q_k-Q_*\rVert_\infty$ against episodes for MC control, Sarsa and Q-learning at fixed $\alpha,\varepsilon$.
Wall-clock costMilliseconds per solver for the same tolerance, on the same machine and grid.
Traces and planningEpisodes to a target $\lVert Q-Q_*\rVert_\infty$ for $\lambda\in\{0,0.5,0.9\}$ and Dyna $n\in\{0,5,20\}$.

Then perturb the MDP: raise the slip, remove the step cost, open a second corridor. The ranking of the sample-based learners is not stable across those edits, and the exact solvers barely notice.

The model is the dividing line. Dynamic programming buys accuracy with computation and needs $P,R$ up front; TD control buys it with experience and needs neither. Dyna is the bridge — it learns the model it was denied and then spends computation on it.

That bridge is where the rest of the course goes: replace the table with a function approximator and the same Bellman backups become DQN, policy gradients, and eventually the alignment loop in Part IV.
